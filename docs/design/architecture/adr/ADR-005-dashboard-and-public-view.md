# ADR-005 — Private dashboard and public view

Status: Accepted
Date: 2026-10-26
Decision owners: the author
Accepted by: the author, 2026-10-26, «SSH tunnel + static site (Recommended)»
Related: CAP-004, CAP-005, FR-027 to FR-033, NFR-009, NFR-011, CON-002, CON-003, CON-007

## Context
- The private dashboard is seen only by the author (CON-002) and shows private positions and parameters.
- The public view is read-only and must not show anything private (FR-033, CON-003).
- The system runs on a local Linux VM of the author (ADR-001).
- Exposing the private dashboard to the internet opens an attack surface.

## Decision Drivers
- That nothing private leaks by mistake (FR-033).
- Zero exposed surface for what is private.
- Zero or near-zero cost for what is public (NFR-006).

## Options Considered
### Option A — A single web application on the VPS, with login for the private part
- Benefits: a single system for both views.
- Costs/risks: the private part is exposed on the internet behind a login. A permissions mistake publishes private data. Authentication also has to be maintained.

### Option B — Private dashboard reachable only through an SSH tunnel, and public view as a generated static site
- Benefits: the dashboard listens only inside the VM and the author opens it with an SSH tunnel, with no exposed ports. The public view is a static site that an exporter generates with only what is marked public (FR-031). It is published on free static hosting, with no access to the database.
- Costs/risks: the public view is not live; it is updated when the exporter runs (for example, every hour or every day).

### Option C — Private dashboard on the author's computer, reading a copy of the database
- Benefits: nothing exposed on the VM.
- Costs/risks: the copy falls behind and does not meet NFR-009 without constant synchronization.

## Decision
**Option B**.

- The private dashboard is a Python web application, viewed through an SSH tunnel.
- The public view is a static site, generated by an exporter that only reads what is marked public.

## Consequences
### Positive
- The public view code never touches private data: the exporter filters before generating.
- No VM port is left open, except SSH inside the local network.

### Negative / Trade-offs
- The public view has the exporter's lag.
- Viewing the dashboard requires opening an SSH tunnel.

## Verification / Revisit Trigger
- An automated test verifies that the generated site contains no parameters, positions or hourly series of private methods (FR-033).
